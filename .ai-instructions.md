# AI Instructions - Xperience by Kentico K13 E-Commerce Integration

## Project Overview

**Xperience by Kentico - Kentico Xperience 13 E-commerce** is a bridge integration that enables existing Kentico Xperience 13 (KX 13) E-Commerce projects to migrate to the new Xperience by Kentico (XbyK) platform while maintaining e-commerce functionality from KX 13.

**Key Purpose**:

- Provides a REST API layer (Store API) on KX 13 to expose e-commerce features
- Supplies integration libraries for XbyK to consume KX 13 e-commerce data
- Enables flexible e-commerce scenarios ranging from simple product listings to full-scale migrations
- Facilitates gradual migration paths for existing KX 13 e-commerce projects

**Repository**: [Kentico/xperience-by-kentico-k13ecommerce](https://github.com/Kentico/xperience-by-kentico-k13ecommerce)

## Integration Scenarios

### 1. **Simple Product Listing** (Lightweight)

- Display products from KX 13 on XbyK pages
- Product listing widget shows KX 13 products directly
- Purchases redirect to KX 13 store
- **Use Case**: Landing pages, promotional product displays
- **Example**: `StoreProductListWidgetViewComponent.cs` in sample project

### 2. **Full-Scale E-Commerce Migration** (Comprehensive)

- Product data synchronized to XbyK Content Hub
- Product listing, detail pages, and checkout on XbyK
- Shopping cart managed on KX 13 (calculated and stored)
- Orders created from cart, stored on KX 13
- Product pages manually linked or auto-synchronized from Content Hub
- **Use Case**: Complete e-shop migration from KX 13 to XbyK
- **Example**: DancingGoat-K13Ecommerce sample project

## Core APIs & Services

### Store API Endpoints (KX 13 - Running on `Kentico13_DancingGoat`)

**Base Path**: `/api/store/`  
**Authentication**: OAuth 2.0 Bearer Token (JWT)

| Prefix                  | Purpose                  | Sample Operations                                    |
| ----------------------- | ------------------------ | ---------------------------------------------------- |
| `/api/store/auth`       | Authentication           | GET token via client credentials                     |
| `/api/store/products`   | Product catalog          | List products, get categories, pricing, inventory    |
| `/api/store/cart`       | Shopping cart operations | Add/remove items, set delivery, calculate totals     |
| `/api/store/orders`     | Order management         | Create orders, retrieve order history, update status |
| `/api/store/currencies` | Currency support         | List available currencies                            |
| `/api/store/cultures`   | Culture/language support | List supported cultures                              |

**Documentation**:

- Swagger UI: `[K13_Project_URL]/swagger`
- Swagger JSON: `[K13_Project_URL]/swagger/storeapi/swagger.json`

### XbyK Integration Services (`Kentico.Xperience.K13Ecommerce`)

Key services for developers:

- **`IShoppingService`** - High-level cart operations (add items, checkout, etc.)
- **`IOrderService`** - Retrieve and manage orders
- **`IProductService`** - Query and retrieve products with filters
- **`ICurrencyService`** - Currency handling
- **`IAuthenticationService`** - OAuth token management
- **`IProductSyncService`** - Sync products to Content Hub

## Deployment Guide

### Prerequisites

1. **Licenses**: Valid license keys for both KX 13 and XbyK
2. **SQL Server**: SQL Server 2022 Express or higher
3. **.NET SDK**: 8.0 or newer
4. **Node.js**: 20.10.0 or newer

### Development Setup

#### 1. Initial Database Setup

```powershell
cd .\scripts\
.\Init-Project.ps1
```

This script:

- Unzips database backups from `/database` folder
- Restores both KX 13 and XbyK databases
- Prompts for license key insertion
- Applies hotfixes to XbyK
- Runs CI restore on both databases

#### 2. Import License Keys

**For KX 13** (via SQL Management Studio):

```sql
INSERT INTO [dbo].[CMS_LicenseKey]
VALUES ('localhost', 'YOUR_K13_LICENSE_KEY', 'X', 'mm/dd/yyyy', 1);
```

**For XbyK** (via SQL Management Studio):

```sql
UPDATE CMS_SettingsKey
SET KeyValue='YOUR_XBYK_LICENSE_KEY'
WHERE KeyName='CMSLicenseKey'
```

#### 3. Build the Solution

```powershell
dotnet build Kentico.Xperience.K13Ecommerce.sln
```

#### 4. Restore Dependencies (if needed)

```powershell
# For frontend components
cd .\examples\DancingGoat-K13Ecommerce\
npm install
```

#### 5. Run Sample Projects

**Option A: Using VS Code task**

```
Run task: "dotnet: watch DancingGoat"
```

**Option B: Using command line**

```powershell
# Terminal 1 - Run XbyK DancingGoat
dotnet watch run --project examples\DancingGoat-K13Ecommerce\DancingGoat.csproj

# Terminal 2 - Run KX 13 DancingGoat (Store API)
dotnet watch run --project examples\Kentico13_DancingGoatStore\Kentico13_DancingGoat.csproj
```

## Usage Guide

### For XbyK Developers (Consuming K13 Data)

#### 1. Install NuGet Packages

```xml
<PackageReference Include="Kentico.Xperience.K13Ecommerce" Version="3.0.0+" />
<PackageReference Include="Kentico.Xperience.Store.Rcl" Version="3.0.0+" />
```

#### 2. Configure Services

In `Program.cs`:

```csharp
services.AddKenticoStoreServices(configuration);
// This registers all necessary services including IShoppingService, IProductService, etc.
```

#### 3. Use Store Services

```csharp
public class ProductListComponent : ViewComponent
{
    private readonly IProductService _productService;

    public ProductListComponent(IProductService productService)
    {
        _productService = productService;
    }

    public async Task<IViewComponentResult> InvokeAsync()
    {
        var products = await _productService.GetProductsAsync(
            pageSize: 10,
            pageNumber: 1,
            categoryId: "electronics"
        );
        return View(products);
    }
}
```

#### 4. Access Store API Directly (if needed)

Use the generated NSwag client for direct REST API calls:

```csharp
var client = new StoreApiClient(httpClient);
var token = await client.GetAuthTokenAsync(clientId, clientSecret);
var products = await client.GetProductsAsync(token, filter);
```

### For KX 13 Developers (Providing Store API)

#### 1. Install Store API Package

```xml
<PackageReference Include="Kentico.Xperience.StoreApi" Version="1.0.0+" />
```

#### 2. Register Store API in Startup/Program

```csharp
services.AddStoreApi()
    .AddStoreApiSwagger();
app.UseStoreApi();
```

#### 3. Configure OAuth Credentials

In `appsettings.json`:

```json
{
  "StoreApi": {
    "Enabled": true,
    "ClientId": "your-client-id",
    "ClientSecret": "your-client-secret"
  }
}
```

#### 4. Access via Swagger

Navigate to `https://localhost:5001/swagger` to explore all available endpoints.

### Product Synchronization to Content Hub

**What syncs**: Products, product variants, images, categories, prices  
**When**: On schedule or manually triggered  
**Configuration**:

1. Enable product synchronization in XbyK settings
2. Map KX 13 products to XbyK content types
3. Run initial sync via administration UI or code

### Shopping Cart Workflow

1. **Create/Load Cart**: Initialize from `ShoppingCartGUID` in session
2. **Add Items**: Call `IShoppingService.AddProductToCartAsync()`
3. **Update Quantities**: Modify cart items
4. **Set Delivery**: Configure shipping address and method
5. **Calculate Totals**: Cart is calculated on KX 13
6. **Create Order**: Convert cart to order (stored on KX 13)
7. **Display on XbyK**: Retrieve order history via `IOrderService`

## Key Concepts

### Store GUID vs. Shopping Cart GUID

- **Store GUID**: Identifies the KX 13 e-commerce store (configured in Store settings)
- **Shopping Cart GUID**: Uniquely identifies a shopping cart session; passed in HTTP headers to API

### Content Hub Product Synchronization

Products can optionally be synchronized from KX 13 to XbyK Content Hub:

- Creates content items for products in Content Hub
- Enables content management and publishing workflows in XbyK
- Allows manual content enrichment and linking to pages
- Can be turned off if only API-based product listing is needed

### User Context in Store API

- API uses OAuth with optional `user_email` parameter
- When email provided: token embeds user claims (sub, name)
- User must exist and be enabled in KX 13
- Without email: API operates in public user context

## Troubleshooting & Tips

### Database Issues

1. **License key errors**: Ensure license keys are inserted correctly and dates are valid
2. **Database won't restore**: Check SQL Server is running, backups exist in `/database`
3. **CI restore fails**: Verify CI is enabled and license is valid

### API Connection Issues

1. **401 Unauthorized**: Check OAuth credentials and token validity
2. **404 Not Found**: Verify Store API is running on correct URL
3. **CORS errors**: Configure CORS in Store API project if calling from different domain

### Frontend Build Issues

1. **npm install fails**: Ensure Node.js 20.10.0+ is installed
2. **Webpack compilation fails**: Check for conflicting versions in `package-lock.json`
3. **Hot reload not working**: Verify webpack dev server is running on correct port
